# lex · 我的英语学习库

线上地址：https://lxy-187.github.io/English/

一个零依赖、零构建的静态网页。**直接双击 `index.html` 就能用**，也可以放到任何静态托管上（GitHub Pages / Vercel / 自己的 NAS）。

数据和界面完全分离 —— 你平时只需要编辑 `data/` 里的四个文件，界面会自动更新，不用碰任何代码。

---

## 板块结构

| 板块 | 路由 | 文件 | 内容 |
|---|---|---|---|
| 概览 | `#/home` | — | 统计、今日三则（每天自动轮换）、最近加入 |
| **单词分析** | `#/words` | `data/words.js` | **核心图景 → 多维义项 → 构词 → 边界与关联 → 易错点 → 自测** |
| 词根词缀 | `#/roots` | `data/roots.js` | **每层含义自成一节**，派生词挂在它所属的那层下面 |
| 范文解析 | `#/essays` | `data/essays.js` | 以**考研真题**为主，按年份／考试／题型／主题分类；点进去看提纲 + 逐句批注 |
| 我的收藏 | `#/starred` | localStorage | 任意条目点星号即可收藏 |
| 偏好设置 | `#/settings` | localStorage | 主题、复习范围、重置；整页由注册表生成 |

**一个词的所有信息都在它自己的页面上。** 曾经的「关键辨析」板块已经按词拆开并入 `data/words.js`：
一组辨析里，每个词拿走属于自己的核心义、细微差别和例句，同组其他词进它的「边界与关联」，
点名它的易错点和自测题跟着走。所以不存在「这个词的辨析在另一个板块」这回事。
（曾经的「好词好句」板块已移除。）

**导航模型**：单词、词根、范文都是「卡片墙 → 独立页面」。列表页只放卡片，一屏能扫完；点进去是一个只有这一个条目的干净空间（阅读栏宽 820px），左上角返回。不做左右分栏，避免列表和内容互相干扰。

**侧栏只有图标**，名称走 `title` 与 `aria-label`，鼠标悬停可见；分组用一条 `.5px` 分隔线代替小标题。
名称文字始终写在 DOM 里（桌面用 CSS 藏起来），一是给读屏，二是手机抽屉要展开显示——
那里没有 hover，只给图标等于让人猜。

**手机上没有常驻侧栏**：同一个 `.rail` 元素改成从左侧滑出的抽屉，顶栏左上角是开关，
点遮罩、点某个板块、按 Esc 都能关。右下角常驻一颗「随机复习下一条」，
和桌面导轨底部那颗是同一个动作两个入口。

**视觉材质**：照 Apple HIG 的两层模型建，细节见下面的「设计规范」一节。
悬浮的只有侧栏、顶栏、标签栏、浮层和药丸控件；卡片是平的。

**色彩系统**：界面本身全是中性灰——导航、按钮、胶囊、卡片、背景一概不上色。
主题色只染**正文里有意义的字**：释义、词根、跳转链接、搜索命中、范文批注、练习答案。
另有一个功能色（琥珀）只出现在两处：易错点的感叹号、已收藏的星号。

**构词成分本身就是链接**。`parts` 里的每一段会去 `data/roots.js` 找对应词条：
找得到就直接点进那个词根页；找不到就画一条虚线下划线，点一下提示条目还没建。
所以详情页不再单独列一行「相关词根」——成分就是入口。

## 怎么追加内容

三个数据文件都是同一个模式：打开文件，照着已有条目再写一个，逗号别漏。保存后刷新页面即可。

### 1. 加一个单词分析 → `data/words.js`

这个板块回答的不是「这个词翻译成什么」，而是「它描绘的是什么场景/动作/状态，为什么同一个词能长出这么多中文释义」。

```js
{
  id: "convert",
  w: "convert",
  pos: "v./n.",                  // 可省略
  core: "一句话说清它描绘的本质状态",     // 核心图景
  image: "一个具体的比喻/画面，让核心可记",  // 脑海图景
  origin: "拉丁语：com-（彻底）+ vertere（翻转）",   // 词源，可省略
  // 构词拆解。形式能对上 data/roots.js 里某个条目时，页面自动生成双向链接
  parts: [["con-", "彻底地", "prefix"], ["vert", "翻转", "root"]],
  rootRefs: ["com"],             // 也可以显式指定要关联的词根 id
  senses: [{
    dim: "物理形态与功能的底层重置",   // 这一维度叫什么
    tag: "工程",                      // 维度标签
    scene: "描绘场景：这个义项在现实中长什么样",
    feature: "状态特征（可省略）",
    zh: "转换、改造、折算",            // 对应中文释义
    ex: [{ en: "Convert USD into Euros.", zh: "把美元兑换成欧元／价值不变，但结算协议切换了。" }]
  }],
  // 边界对比。若 w 也是本库条目，自动互相链接；不是也没关系，会降级成纯文本
  contrasts: [{ w: "subvert", note: "同根 vertere：subvert 是从底部掀翻，convert 是原地变轨。" }],
  summary: "一句话带走（可省略）"
}
```

> **双向链接怎么工作**：你只需要写单向。在 `convert` 里写了 `contrasts: [{w:"subvert"}]`，`subvert` 的页面会自动出现一条「被提到 · convert」的反向链接；在 `parts` 里写了 `vert`、或在 `rootRefs` 里写了 `com`，对应词根页会自动多出一节「用到它的单词剖析」（`parts` 里的每一段同时会变成可点的跳转入口）。不需要在两边各写一遍，也不会重复显示。指向尚未收录的词会降级成纯文本而不是断链，等你补上词条，链接自动接通。

> **访问栈**：顺着链接一层层跳进去时，详情页顶部会累积一条访问路径（如 `pervert › subvert › convert`）。点其中任意一层即可原路退回，该层之上的记录同时弹出。走到任何列表页则清空。路径存在 sessionStorage，刷新不丢，关掉标签页即重置。

### 2. 加一个词根 → `data/roots.js`

**结构原则：含义决定框架。** 一个词缀有几层意思，就写几节；每个派生词挂在它真正所属的那层下面。不存在固定节数——`ject` 只有 2 层，`per-` 有 5 层。

```js
{
  id: "grat",                    // 唯一 id，用作链接地址
  kind: "root",                  // root 词根 | prefix 前缀 | suffix 后缀
  form: "grat / grac",           // 显示的形式，多个变体用 / 分隔
  meaning: "感谢、令人愉快",       // 总括释义，用于卡片和搜索
  gloss: "pleasing, thankful",
  origin: "拉丁语 gratus",
  senses: [                      // ← 每一层含义一节，节数由这个词缀自己决定
    {
      meaning: "心怀感谢",         // 这一节的标题
      gloss: "thankful",          // 可省略
      note: "这一层怎么理解。只讲这一层，别把其他层的意思混进来。支持 **粗体**。",
      words: [
        {
          w: "gratitude",
          // 构词拆解：[形式, 含义, 类型]，类型必须是 prefix / root / suffix
          parts: [["grat", "感谢", "root"], ["-itude", "名词", "suffix"]],
          def: "感激",
          ex: "She expressed her gratitude to the team."   // 可省略
        }
      ]
    },
    {
      meaning: "令人愉快、讨喜",     // 第二层，词挂在自己这层下面
      note: "……",
      words: [ /* … */ ]
    }
  ],
  related: ["cred"]              // 相关词根的 id，可空数组
}
```

详情页会按这个结构渲染：顶部一条「N 层含义」总览，下面每层一个可折叠小节（带序号徽标），每层内部才是属于它的派生词。折叠状态按「这个词缀的第几层」单独记忆，不同词缀之间互不干扰。

### 3. 加一篇范文 → `data/essays.js`

```js
{
  id: "ky2005-1",              // 唯一 id，考研真题建议用 ky<年份>-<序号>
  title: "中文标题",
  // ↓ 四个分类字段决定它在页面上怎么被筛选和分组
  exam: "考研英语一",           // 考研英语一 / 考研英语二 / 雅思 / 四六级 / 其他
  year: 2005,                  // 真题年份；不是真题写 null，会归到「非真题」组
  part: "大作文",               // 大作文 / 小作文 / Task 1 / Task 2 …
  topic: "社会",                // 社会 / 教育 / 环境 / 文化 / 科技 …
  genre: "图画作文 · 现象解释",
  level: "高分档",
  words: 180,
  prompt: "英文题目原文（图画题可写图画描述 + 写作要求）",
  outline: [{ label: "第 1 段 · 引入", purpose: "这一段要干什么" }],
  paragraphs: [{
    role: "引入段",
    text: "英文正文原文（整段）。",
    notes: [
      // ⚠️ mark 必须是 text 里【一字不差】出现的片段（含大小写和标点）
      //    页面会自动把它高亮，点击展开右边的讲解
      { mark: "英文正文原文", note: "为什么这么写好。支持 **粗体**。" }
    ],
    analysis: "整段的点评，显示在段落下方的灰框里。可省略。"
  }],
  highlights: [{ en: "可迁移的表达", zh: "中文", why: "什么场景能用上" }],   // 可省略
  takeaway: "一句话带走。"                                                  // 可省略
}
```

> **批注对不上怎么办**：如果某条 `mark` 在 `text` 里找不到，页面会静默跳过它（不会报错也不会崩）。发现某句点不开，先检查 `mark` 是不是和正文有一个字符的出入 —— 最常见的是连字符、撇号、空格数量不一致。

## 折叠与排序

**列表页**（单词分析 / 词根词缀 / 范文解析）顶部只有一个「视图」按钮，筛选和排序都收在里面，按钮上直接显示当前状态（例如 `前缀 · 派生词量`）。点开面板连续调整不会关闭，点面板外面或按 Esc 收起。

排序方式同时决定分组方式，每组独立折叠，右侧一键全部折叠／展开。

| 板块 | 只看（筛选） | 排序 / 分组 |
|---|---|---|
| 单词分析 | — | 字母（默认）· 义项数 · 关联 · 收藏 |
| 词根词缀 | 全部 / 词根 / 前缀 / 后缀 | 字母（默认）· 类型 · 派生词量 · 义项数 · 收藏 |
| 范文解析 | 全部 / 考研英语一 / 考研英语二 / 雅思 / … | 年份（默认，倒序）· 考试 · 题型 · 主题 · 收藏 |

### 卡片样式

面板里第三组是「卡片」，三档，每个板块可以分别设置，存在 localStorage：

| 样式 | 卡片上显示 |
|---|---|
| **极简**（默认） | 只有英文本身。释义、例句、用法全部进详情页再看 |
| **标准** | 英文 + 一行中文 |
| **详细** | 完整信息：类型角标、英文释义、派生词预览、条目数 |

极简下卡片密度最高（1440px 宽时词根一行能排 8 张），星号悬停才浮现，触摸设备上常驻。

首字母分组会自动剥掉后缀条目开头的连字符，`-able / -ible` 归入 **A**，`-tion` 归入 **T**。

**详情页**：每个部分都能单独折叠 —— 单词页是「核心图景 / 构词与词源 / 义项 / 边界与关联 / 易错点 / 自测 / 一句话带走」（后四项按条目有无自动出现），词根页是「每层含义各一节 + 相关词根 + 用到它的单词剖析」，范文页是「题目 / 结构提纲 / 正文与批注 / 可迁移表达 / 一句话带走」。

折叠状态按**部分**记忆而不是按条目记忆：在某个单词页折叠了「核心图景」，之后打开任何一个单词都是折叠的（词根的义项节例外，它按「哪个词缀的第几层」单独记）。想只看派生词、只做自测、只读正文，设置一次就一直生效。排序方式和折叠状态都存在 localStorage，刷新和跨页都保留。

想加新的排序方式，改 `app.js` 里的 `SORTS` 对象：`group` 函数返回分组名，`order` 数组指定组的先后，`cmp` 决定组内排序。

## 单词标签

单词页标题下面常驻一条标签栏，分三组。区别不在「值由谁填」——三组的值都由你点——
而在**词表由谁定**：

| 组 | 词表 | 互斥 | 说明 |
|---|---|---|---|
| 掌握度 | 系统固定 | **是** | 掌握 / 熟悉 / 模糊 / 不认识。再点一次当前值＝取消，回到未标记 |
| 考纲 | 系统固定 | 否 | 考研 / 雅思 / 托福 / 四六级 / GRE / PTE，一个词可以同时属于多个 |
| 自建 | 你自己攒 | 否 | 用过的会进候选，下次输入时自动补全。一个词最多 8 个，每个最长 12 字 |

**关于考研**：本库整体就是考研范围，所以每个词都标一遍等于没标，标不标都行。
真正有信息量的是标出它**在别的考试里也考**。但要注意「空着」只表示**还没标过**，
不代表「只考考研」——所以按考纲分组时那一组叫「未标考纲」，不叫「仅考研」。
不替用户断言他没说过的事。

### 加一组标签

改 `app.js` 的 `TAG_SETS`，和 `PREFS` 是同一个套路：

```js
{ id: "mastery", label: "掌握度", exclusive: true,   // exclusive 决定互斥
  hint: "复习时随手改，只能选一个",
  options: [["known","掌握"], ["familiar","熟悉"], ["vague","模糊"], ["unknown","不认识"]] }
// 或者 free: true，表示词表由用户自己攒，不写 options
```

标签栏、卡片圆点、排序分组、筛选都从这里派生。

### 存储与校验

存在 `el.tags`，结构 `{v, items: { 单词id: {mastery, exam[], custom[]} }}`。
读取时按注册表全量清洗：词被删了就丢掉它的标签，选项改过就丢掉认不出的值，
自建标签统一去空格、去重、截断。清洗结果会写回，不会每次都重洗一遍。

### 颜色

掌握度四档各有一个色，走的是**内容色**那条规则——它说明的是这个词的状态，不是装饰容器。
一律用 `.15`–`.18` 的低透明度填充，够区分即可，压在正文之下：

| | 掌握 | 熟悉 | 模糊 | 不认识 |
|---|---|---|---|---|
| 含义 | 绿 | 蓝 | 琥珀 | 红 |

考纲用中性填充（并列的类别，颜色给不出额外信息），自建用主题色。
卡片左上角的小圆点和标签胶囊共用同一套变量，所以列表页扫一眼就知道哪些没掌握。

### 列表页的用法

- **只看掌握度**：视图面板里按档筛选，带实时条数（例如「不认识 6」）
- **按掌握度分组**：顺序是不认识 → 模糊 → 熟悉 → 掌握 → 未标记，**最该复习的排最前面**
- **按考纲分组**：能看出哪些词跨考试

## 偏好设置

### 什么该进设置，什么不该

Apple HIG 的原则是「大多数 app 都不需要设置」：主界面放常改的选项，设置里只放**极少改、
且在页面里没有自然归宿**的。所以这里刻意只有三条——

- **排序、分组、卡片样式**不在设置里。它们改得频繁，留在各列表页的「视图」面板中，
  就近调整、即时看到效果。
- **筛选状态**（只看前缀、只看某年真题）也不进设置。它是一次浏览的临时状态，不是偏好。

每加一条设置前先问：它一年会被改几次？如果超过几十次，它就该待在主界面上。

### 架构：一处声明，四处派生

设置项写在 `app.js` 的 `PREFS` 数组里，一条一个对象：

```js
{ id: "review.essayParts", group: "复习", label: "范文题型",
  hint: "只背小作文或只背大作文，在这里勾",
  type: "set",                                   // enum 单选 | set 多选
  def: ESSAY_PARTS.slice(),
  options: ESSAY_PARTS.map(v => [v, v]),         // 选项从数据里数出来
  when: () => prefs.has("review.scope", "essays"),   // 依赖条件
  whenHint: "「复习范围」里没有勾选范文解析，这一条暂时不生效" }
```

`options` 可以从数据里长出来：`ESSAY_PARTS` 是把 `data/essays.js` 里的 `part` 字段去重、
按条数排序得到的。**数据里加一种新题型，设置页自动多一个开关，不用改代码。**

`when` 声明依赖关系。条件不满足时那一行变淡、开关点不动、说明文字换成 `whenHint`——
但**位置留着**，不隐藏。隐藏会造成布局跳动，比变淡更难受。

**加一条设置就是往这个数组里加一个对象。**存储、设置页的界面、读取时的校验、
「恢复默认」四件事全部自动跟上，不需要在任何别的地方写代码。设置页整页是由这个
数组渲染出来的，没有一行是为某个具体设置手写的。

### 三条不能省的规则

1. **存进来的东西一律不可信。** localStorage 里的数据活得比代码久：可能是旧版本写的，
   可能被手动改过，也可能是另一个标签页写的。所有值在读取时都要对着 `options` 校验，
   坏值退回默认（`prefs.clean()`）。写 `theme: "neon"` 进去不会让页面崩，只会退回跟随系统。

2. **版本号 + 迁移，而且要写回。** 存储结构是 `{ v: 1, values: {...} }`。版本对不上就走
   `migrate()`，把旧数据升上来。**升完必须存回去**——只在内存里迁移，下次打开又丢了
   （这个坑真踩过：老的 `el.theme` 读出来用了，但没写进新键，第二次刷新主题就没了）。

3. **不合法的状态在界面上就该点不出来。** 「复习范围」不许把最后一项也关掉，因为空范围
   会让随机复习直接失效。与其事后报错，不如在 `toggle()` 里拒绝并给一句提示。

4. **改一个开关不要重画整页。** 设置页最初是每次点击都 `onRoute()` 重渲染，结果是
   DOM 全部重建、入场动画重放、滚动位置被拉回顶部——点一下底部的开关屏幕就跳一次。
   现在走 `syncPrefUI()`：只改受影响节点的 `is-on`、`aria-pressed`、`disabled` 和提示文字。
   判断有没有做对，看两件事——**记号节点还在不在，滚动位置有没有变**。

5. **一旦有了「渲染」和「就地更新」两条路径，状态的判断只能写一处。** 这是上一条的代价，
   也是真踩过的坑：`disabled` 和 `prow--off` 当时只在 `syncPrefUI()` 里加，初次渲染没加。
   于是取消勾选后当场是灰的，**切到别的页面再回来（＝重新渲染）就又变成可点的了**。
   现在两条路径共用同一个谓词 `prefOff(d)`，渲染时写进 HTML，同步时写进 DOM 属性。
   回归测试要专门覆盖「离开再回来」和「刷新后」这两条重新渲染的路径，
   光测「点击之后」是发现不了的。

   附带的第二个 bug：因为 `prow--off` 没加上，CSS 里的 `pointer-events: none` 也没生效，
   那些看起来禁用的开关其实点得动、真的会改偏好。所以事件处理里也补了 `!el.disabled` 判断——
   **视觉禁用和行为禁用要分别落实，不能指望其中一个。**

同一条原则也适用于已有的存储：板块删掉之后，它写的 `el.stars`、`el.sorts` 键还在，
所以 `store.load()` 会把认不出来的键丢掉，顺手清掉指向已删板块的孤儿收藏。

### 存储键

| 键 | 内容 | 说明 |
|---|---|---|
| `el.prefs` | `{v, values}` | 偏好设置，带版本号 |
| `el.stars` | `["words:commit", …]` | 收藏，读取时按板块前缀过滤 |
| `el.sorts` / `el.cards` | 每个板块的排序与卡片样式 | 读取时按当前合法值过滤 |
| `el.folds` | 折叠状态 | 缺省为展开，只记住被折叠的 |
| `el.trail`（sessionStorage） | 访问栈 | 关标签页即失效 |

## 小功能

- **⌘K / Ctrl+K** 聚焦搜索框。搜索覆盖全部三个板块，且分两层：
  - **卡片**（单词、词缀、范文各自的条目）——除了正文，它自身的**分类信息也进索引**，所以可以直接搜「前缀」「后缀」「高频易错」「雅思」「Task 2」「教育」这类分类词，把整类卡片调出来。单词的对比说明、易错点和自测题也在索引里，所以搜 `have an effect on` 能直接命中 effect。结果里带「卡片」徽标、填充更实。
  - **片段**（一层义项、一个派生词、一条可迁移表达）——搜具体内容时命中。
  - 同等匹配下**卡片排在片段之前**；结果顶部有按板块筛选的 chips（全部 / 单词分析 / 词根词缀 / 范文解析），带各自条数。
- **星号** 收藏任意条目，存在浏览器本地（localStorage），换设备不同步。
- **随机复习一条**（左下角骰子）从「复习范围」里抽，范围可以细到题型：
  板块层面勾「范文解析」，再在「范文题型」里只勾「小作文」，抽到的就只有小作文。
  词根同理，可以只背前缀或只背后缀。按钮的悬停提示会显示当前范围和池子里有多少条
  （例如「范文解析（小作文）（7 条）」）。默认不会连着抽到同一条。
- **主题按钮** 在 跟随系统 → 浅色 → 深色 之间循环。
- **骰子按钮** 随机跳到一条词根／辨析／范文，用来做无目的的复习。
- **打印**：Ctrl+P 会自动隐藏导航栏，可以把某个词根或范文打成复习纸。

## 设计规范

界面照 Apple HIG 的**两层模型**建，材质参数取自 Apple Podcasts 线上样式表。
改样式前先读这一节，`assets/css/styles.css` 顶部的注释是同一套话的短版。

### 两层，边界不能含糊

| | 功能层（悬浮） | 内容层（平面） |
|---|---|---|
| 是谁 | 侧栏、顶栏、手机标签栏、浮层面板 | 卡片、行、区块、正文 |
| 材质 | 半透明 + `saturate(220%) blur(16px)` | 纯填充色 |
| 边 | 四周等宽 `.5px` 内描边（`--rim`） | 没有边 |
| 影 | 全向 `0 10px 40px` | 静止时没有影子，悬停才抬起 |

HIG 原话：*"Don't use Liquid Glass in the content layer."* 卡片不许用玻璃、不许加模糊、
不许加顶部高光——内容层只有填充色和 `.5px` 分隔线。

### 硬性要求

1. **不许给盒子画轮廓。** 全站 `border: 1px solid` 应当为 0 条。要区分两个东西，
   用填充深浅、用间距、用 `.5px` 分隔线，不用把它框起来。
2. **描边四周必须等宽。** 只有悬浮件有描边，写法是四条 `.5px` 内阴影一边一条
   （见 `--rim`），颜色透明度完全相同。不许只画顶部高光或单边线。
3. **不许有单边装饰条。** 左侧 3px 竖条、选中项伸到容器外的指示条、引文左边线，
   一律换成整块填充或纯缩进。
4. **悬浮件与窗口边缘留等距 `--gap`（12px）。** 上下左右一样。
5. **内容要能从悬浮件底下透出来。** 这是要求，不是疏漏——
   手机上正文会从浮起的标签栏下面露出一角，桌面上正文会从顶栏的模糊里滚过去。
   HIG 明确要的就是这个：*"Liquid Glass allows content to scroll and peek through
   from beneath these elements to give the interface a sense of dynamism and depth."*
   **不要**为了「干净」把它盖死，也不要给标签栏加不透明底把下面的内容切断。
   顶栏用渐隐遮罩做滚动边缘（模糊 + 压底 + 下沿渐隐），保证浮起来的字够清楚就行。
6. **颜色只上在内容上。** 导航、按钮、胶囊、卡片、标签栏、背景一律中性灰。
   主题色（`--key`）只染正文里有意义的字：释义、词根、跳转链接、搜索命中、
   范文批注、练习答案。收藏星标用 `--warn`。
7. **文字用同一个颜色的不同透明度**，不要一串灰色号：`.88 / .55 / .38`
   （对应 Apple 的 primary / secondary / tertiary）。填充同理：`.05 / .10 / .16`。

### 响应式

| 屏幕宽度 | 布局 | 词根卡片列数 |
|---|---|---|
| ≥ 1100px | 浮起的完整侧栏（列宽 232px，面板 208px）+ 卡片墙 | 5 |
| 760–1099px（平板） | 浮起的图标导轨（列宽 102px，面板 78px）+ 卡片墙 | 3 |
| 360–759px（手机） | 左侧可折叠抽屉 + 右下角随机复习按钮，安全区适配 | 2 |
| < 360px | 同上 | 1 |

触摸设备上按钮点击区会自动放大到 40px。
系统开了「降低透明度」时，所有玻璃退回实色、关掉模糊（见样式表末尾）。

## 图标与添加到主屏

`assets/icon/` 下是同一套设计的几个尺寸，配 `manifest.webmanifest`：

| 文件 | 用途 |
|---|---|
| `icon.svg` | 浏览器标签页（矢量，任何尺寸都清楚） |
| `favicon-32.png` | 不支持 SVG 图标时的兜底 |
| `apple-touch-icon.png` | iOS「添加到主屏幕」，180×180 |
| `icon-192.png` / `icon-512.png` | Android / PWA |
| `icon-maskable-512.png` | Android 会把图标裁成圆形，这版把字缩进安全区 |

设计上和界面同源：近黑的中性底 + 正文那副衬线字的 lex 字标 + 一点主题色。
iOS 会自己把 apple-touch-icon 切圆角，所以出的是满幅方图，不自己加圆角。
32px 上那颗主题色圆点只会糊成一坨，所以小尺寸那版去掉了它。

重新生成图标：改 `icon.svg` 后用 Pillow 重出 PNG（脚本见提交记录），
或者任何能把 SVG 转 PNG 的工具，尺寸照上表。

## 部署与缓存

推到 `main` 后 GitHub Pages 会自动构建，通常一两分钟内生效。

**但页面很可能看起来没变**——GitHub Pages 给静态资源的响应头是 `Cache-Control: max-age=600`，
也就是 10 分钟内浏览器直接用本地副本，连问都不问服务器。更麻烦的是：如果只有 `index.html`
过期了而 `app.js` 没过期，你会拿到「新 HTML + 旧 JS」的错配状态，那比单纯没刷新更难查。

所以 `index.html` 里所有本地资源都带了版本号：

```html
<link rel="stylesheet" href="assets/css/styles.css?v=202608231809">
<script src="assets/js/app.js?v=202608231809"></script>
```

URL 变了，浏览器就必须重新下载，错配状态不会出现。

**每次推送前先把版本号刷一遍**（一条命令改全部五处）：

```bash
sed -i -E "s/\?v=[0-9]+/?v=$(date +%Y%m%d%H%M)/g" index.html
```

想立刻看到最新版而不等缓存过期，硬刷新即可：Windows / Linux 是 `Ctrl+Shift+R`，
macOS 是 `Cmd+Shift+R`。

## 本地预览

双击 `index.html` 即可。想用本地服务器（推荐，行为和线上一致）：

```bash
python -m http.server 5599
```

然后访问 http://localhost:5599

## 文件结构

```
index.html              页面骨架 + 图标 sprite
assets/css/styles.css   设计系统（令牌 → 基础 → 布局 → 导航 → 组件 → 板块 → 响应式）
                        改之前先看 README 的「设计规范」一节
assets/js/app.js        路由、视图渲染、搜索、收藏、主题、双向链接索引
data/words.js           单词分析（含原关键辨析拆分进来的词条）
data/roots.js           词根词缀
data/essays.js          范文解析
```

想加一个全新板块，在 `app.js` 顶部的 `SECTIONS` 数组里加一项，再写一个对应的 `VIEWS.你的板块名` 函数即可 —— 导航、配色、路由会自动接上。
